## 0. 一句话

## 1. Step 0 —— Customer Access Test(48 小时)

### 1.1 做什么

1. 从个人网络列出 **≥10 位**画像内联系人。
2. 每人发一条**一句话邀请**(见 §1.3)。
3. 记录回复,48 小时后统计。

### 1.2 画像(与 `docs/customer/customer-profile.md` 一致)

| 优先 | 角色 | 为什么 |
|---|---|---|
| P1 | GRC / 合规经理 | 痛点最深、决策链最短 |
| P1 | 内审负责人 | 第二场景 |
| P2 | 四大 / 本土审计咨询的风险顾问 | 观察者 + 渠道情报 |
| P2 | **正在用 Vanta / AuditBoard / Hyperproof 的人** | 红队明确要求**推翻**原 profile 的排除项 —— 这是抽样设计错误 |
| P2 | CISO | 买家画像 |
| P3 | 采购经理 | C3 交叉验证 |

**配额建议**: P1×3、P1(内审)×1、P2(现有工具用户)×1、P2(CISO)×1、P3(采购)×1 = **至少 7 位**。

### 1.3 邀请话术(照抄,不要加形容词)

> 我在做一个审计/合规方向的 AI 产品调研,**想请你聊 30 分钟你们真实的证据准备工作,不推销**。

**纪律**: 不提产品名、不提"平台"、不提"Agent"、不说"我们做了个东西"。任何推销性词汇都会把受访者变成礼貌的听众,而不是信息源。

### 1.4 判定门 —— **Customer Access Test(不是 Problem Validation Gate)**

> ⚠️ **Codex 第二轮判词 §12 修正**：原来把「<5 人应约」写成产品 Kill Criterion 是**错的**。
> 这个测试测的是**你的客户触达能力**,不是**问题是否存在**。
> 联系不上客户,最多说明当前联系人/触达方式有问题,**不能推出这个产品方向应当 Kill**。

| 结果 | 判定 |
|---|---|
| **≥5 人应约** | Access 假设存活 → 进入 Step 0.6 |
| **<5 人** | **Access 假设失败 → 换触达策略**(换渠道 / 换画像 / 找引荐 / 用招聘信号定向),**不杀产品方向** |

**因此本测试的产出是「触达策略是否需要更换」,不是「选题是否成立」。**
真正的选题判定在 §5.1 的访谈打分与 §5.3 的 Kill Criteria(那些测的是问题本身)。

## 2. Step 0.6 —— 中国三问(每位合规/审计/法务受访者必问)

**先问,不看 Demo。** 这三问验证的是"私有化 + 国产开源模型"这条主路径的**前提是否真实存在**。

### 问 1 —— 监管真实性

> 你们现在**实际在做**哪些周期性的合规/审计工作?
> (提示:ISO27001 年审 / 等保测评 / 内控检查 / 个保合规审计 —— 问清**是自行审计还是委托第三方**)

**为什么问**: 红队 G2 指出原 MVP scope 明确排除了 ISO27001,而真正撑起中国可达市场的是等保/内控/个保审计。**如果受访者一个都没在做,这个市场不存在。**

### 问 2 —— 模型部署形态

> 你们现在用的模型是什么形态?
> (自部署开源 / 国内 API / 没有 / **外部 API 被禁止**)

**为什么问**: 验证"模型不出域"是硬约束还是我们的想象。

### 问 3 —— 私有化决策链

> 如果要在你们内部部署一套系统,**谁签字、从哪个预算出**?

**为什么问**: 决定 POC 的可行路径与销售周期。答不出决策人 = 没有真实采购路径。

## 5. 判定门

### 5.1 每场打分

```
Score = 0.3×Severity + 0.2×Pilot意愿 + 0.2×数据可得 + 0.15×Cost + 0.15×Pay信号

≥ 3.5   → POC 推进
2.5–3.5 → 补访谈(累计 ≥8 场)再判
< 2.5   → 回到候选表,启动下一个候选
```

> ⚠️ **以上为计划值,零实测。** 不得当作已验证结论引用。

### 5.2 第 3 场后的假设校准(可证伪)

| 假设 | 若被证伪则 |
|---|---|
| "人工证据类控制是痛点" | 若受访者主要痛在云配置自动测试 → 转向与 Vanta 生态**互补/集成**定位 |
| "准备周期 3–4 周" | 修正 Business Outcome 模型 |
| "内审是第二场景" | 重新加权采购(C3) |
| "愿意给脱敏数据" | POC 改为**客户环境内部署** |

### 5.3 Kill Criteria(任一触发即**重新选题**)

> 注意:以下判据测的是**问题本身是否成立**。
> **「<5 人应约」已从此列表移除** —— 那测的是触达能力,见 §1.4。

1. 5 场中 **≥3 场**:证据准备 <1 人周/年,或已全部外包且无意收回。
2. 5 场中 **≥3 场**:已用 AuditBoard/Hyperproof/Vanta 类平台且明确"够用,不加新工具"。
3. 5 场中 **0 场**愿用脱敏快照做免费 POC。
4. **框架-地域错配**:可达人群中 <2 家在做任何形式的年度审计证据准备。
5. **本土第一推动力缺失**:既无监管强制,也无内部频率驱动。

---

## 6. POC 触发条件(四项全需)

1. ≥2 家确认相同痛点(Severity ≥4 且描述同源)
2. ≥1 家愿提供脱敏真实数据(快照导出亦可)
3. 客户配 1 名技术 + 1 名业务对口人
4. 共同定义成功指标 —— 建议:**单控制项证据归集 ≤10 分钟人工介入;缺口识别召回 ≥80%**
