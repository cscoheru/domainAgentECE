# Demo Script — EvidenceIQ 15 分钟客户演示

> 前提：数据为 Reference Case（NimbusWorks），开场必须声明。
> 环境：本地/单容器运行，`npm run demo`，网络可用（LLM 调用）。
> 目标观众：GRC/合规/内审/采购相关人员（CISO 加分）。

---

## 0–2 分钟｜场景共情

> "假设您是 NimbusWorks 的合规经理 Lin Chen。公司 450 人，SOC2 Type II 审计 6 周后开始，审计期间是上半年。您要为 12 个控制项把证据备齐——政策、访问评审、培训记录、变更单、离职处理……"
>
> "我先说明：NimbusWorks 是我们构建的**演示企业**（Reference Case），数据是模拟的，但它的工作方式和数据形态来自真实审计场景。"

**屏幕**：静态页——NimbusWorks 组织与四系统示意 + 12 控制项清单。

## 2–4 分钟｜传统工作方式与痛点

> "传统做法：Lin 打开 Excel 控制矩阵，逐项去 5 个系统翻证据：Wiki 找政策、Jira 找变更单、HRIS 导离职名单……找到的还要人工判断'够不够、新不新、全不全'。缺的靠邮件催 7 位责任人。去年 Type I：4 周、300+ 封邮件，审计现场还被指出政策版本过期。"

**屏幕**：Before 画面（Excel 矩阵 + 催办邮件瀑布截图）。
**关键台词**："最贵的不是找证据，是**判断证据够不够**——这需要审计专业经验。"

## 4–9 分钟｜Agent 实际运行（现场跑）

**操作**：输入审计范围三要素（SOC2 Type II / H1 2026 / 四生产系统）→ 点击运行。

> 旁白节奏（跟着 UI 步骤面板）：
> 1. **Ingest/Map**："Control Intake Agent 把 12 个控制项映射成证据需求清单——这是我们的**领域本体**：什么控制项需要什么类型、什么频率、覆盖哪些系统的证据。"
> 2. **Retrieve**："Evidence & Gap Agent 逐类检索**企业上下文**——注意这里检索是**权限感知**的。"
> 3. **权限演示**（切视角）："切到普通工程师视角——安全评审记录被过滤了，UI 明确提示'权限不足未检索 5 条'。这在真实环境就是 Glean 的权限继承；我们不自建权限系统。"
> 4. **Reason**："找到了 30+ 条候选，现在开始**充分性推理**。"
> 5. **现场发现缺口**（高潮）："注意 CC6.2——三个系统有评审记录，HR 系统没有。Agent 还识别到一个干扰项：《Q2 评审计划》不是记录，不能作为证据。"

**屏幕**：实时步骤面板（Workflow 7 步逐项点亮）+ Reasoning 流。

## 9–12 分钟｜Reasoning / Evidence / Output 深看

> "点开 CC6.2：三条证据各带**原文链接、日期、签发人**——每条判断可回溯。再看四个缺口："
>
> 1. G1 信息安全政策——**过期 16 个月**（新鲜度规则 R2）
> 2. G2 HRIS 无评审——覆盖度 3/4（覆盖度规则 R3）
> 3. G3 培训完成率 92%——低于 95% 阈值（本体里的合格标准）
> 4. G4 离职权限回收延迟 5 天——违反"当日回收"（规则 R2+知识库）
>
> "这些不是 LLM 的'感觉'，是**规则+本体+检索证据**的推理结论，每条都标注了依据。我们还有一套 20 个案例的**回归评估集**——每次改动规则都跑，保证判断稳定。这层'业务正确性评估'是我们的核心资产，Glean 的平台观测只看采纳率和错误率，不看'审计判断对不对'。"

**屏幕**：Evidence Matrix 全景 + 缺口详情侧栏（规则编号+证据引用）。

## 12–15 分钟｜Action / Value / 下一步

> "缺口不只是列出来——**行动已发出**。"（展示 Mock 工单回执：G2→Emma，截止 7/10）
> "Lin 的工作从'4 周翻系统催人'变成'**审核 Agent 的结论、点确认**'——审批点保留人的最终决定权，这在内审场景是必须的。"
>
> **价值收口**：审计准备 3–4 周→≤3 天；缺口从'审计现场爆炸'变成**提前 4–6 周可修复**。
>
> **自然提问（收尾）**：
> "这套系统跑在企业的统一上下文之上——演示里是模拟数据，真实环境可以直接接到你们已有的知识平台（比如 Glean）或直接连文档/工单系统。**如果把它接入你们自己的数据和系统，让它替你们做审计证据准备，你们愿意试一次吗？**"

## 附录 A：备问答（FAQ）

| 问题 | 回答要点 |
|---|---|
| "这不就是 RAG 吗？" | 检索只是输入；核心是控制-证据本体+四类推理+缺口派工；展示规则编号反证 |
| "数据安全？" | MVP 演示全本地；真实部署跑在客户自己的上下文层内（Glean 在客户侧），我们不存数据 |
| "支持 ISO27001 吗？" | 本体是框架无关的，SOC2 先行，ISO 是扩展点（诚实：v0.1 只做 SOC2 CC 12 项） |
| "和 Vanta/Drata 什么区别？" | 它们做云配置自动测试；我们做人工证据类控制的上下文检索+充分性推理（见 recommended-mvp.md §3） |
| "幻觉怎么办？" | 确定性判断走规则不走 LLM；每条结论带证据引用；NEED_REVIEW 兜底 |
