## 1. A1-A5 现状（A 组）

### A1. 流程（生产 vs 非生产分流）

> 原话: "分为生产性采购和非生产性采购两类，生产性采购由供应链部门发起，生产性采购经理收，经供应链VP、总裁、采购VP审核。非生产性采购（比如海外培训），由业务部发起，非生产性采购经理收，经业务VP、总裁、采购VP审核。"

**关键观察**：
- **双线结构**：生产（供应链 → 供应链 VP → 总裁 → 采购 VP）+ 非生产（业务 → 业务 VP → 总裁 → 采购 VP）
- **多级审批**：4 级（部门 → 经理 → VP → 总裁），**V0 demo 的 `R_SPIKE_REVIEW` 规则只覆盖了"采购经理"1 级**，未覆盖 VP/总裁 多级审批链完整性
- **采购 VP 是终审**（不在采购部发起，是收口）

### A2. 频次 + 单 PR 时长

> 原话: "常规性采购一般年初和年底集中采购审批，特殊情况单独审批，流程 1-3 周左右"

- **频次结构**：年初/年底集中 + 全年单独（即"年度大批量 + 月度零散"）
- **时长**：1-3 周（与 `customer-profile.procurement.md` §1 "PR 跑 1-3 天"假设**不符**，受访者说 1-3 周）→ **校准假设 #1**

### A3. 单 PR 资源消耗

> 原话: "10+ 人，平均 2 周，每人半小时"

- **总人时**：10+ × 2 周 × 4 小时/周 = ≥80 人小时/PR（保守估算）
- 与 `validation-metrics.procurement.md` §1 "≥30 分钟/PR"门槛**严重超标**（实际是 ≥80 小时）

### A4. 最大痛点（**核心信号**）

> 原话: "流程由发起部门到采购经理这个环节非常长，比价最消耗时间，经常被驳回重新提交申请，需求部门提供的材料不够严谨、合规，**比价流于形式**"

**痛点排序（提取自原话）**：
1. **流程链路长**（发起部门 → 采购经理 这一段）
2. **比价最消耗时间**
3. **频繁驳回 + 重新提交**
4. **需求部门材料不严谨/不合规**
5. **比价流于形式**（**形式合规但实质不到位**——这是审计师最在意的）

### A5. 哪步最需专业判断

> 原话: "比价和供应商选择"

- **专业判断集中在"比价 + 选供应商"**——这与 PRD §9 "Domain Reasoning / Guardrails" 一致，**V0 demo 的确定性规则**能做"比价完整性检查"，但**不能做"供应商选择"**（V0 没规则）

## 2. B6-B8 数据与系统（B 组）

### B6. 数据位置

> 原话: "采购审批流程有系统（PR 提交到审批，走 OA portal，但**过程数据不上系统**），有的只是邮件/word/excel 记录，没有打通，信息孤岛"

**关键信号**：
- **OA portal 只承载"提交 + 审批"，中间过程数据（比价记录、协商过程、邮件证据）不在系统里**
- V0 Connector 接口（CSV/JSON/本地）**不直接对接 OA**——这是个**P0 范围扩张**信号：要么做 OA connector，要么承认"我们只读 PR 提交 + 审批结果"（中间数据由客户提供）

### B7. 权限

> 原话: "OA 有权限管理，但是邮件、办公文件之间传递没有权限设置，邮件抄送/暗送常常出问题，发件人乱 cc/bcc"

**关键信号**：
- **OA 内权限 OK + 邮件外权限完全失控**（抄送/暗送导致信息外溢）
- V0 的 `check_user_permission` 走 ACL 表——**邮件外溢不在 V0 防御范围内**（这是邮件系统问题，不是 Context Engine 问题）
- **明确告知客户**："我们管 Context 内的权限，邮件外溢是另一个系统问题"

### B8. 统一知识平台

> 原话: "没有，每个部门独立，采购没有统筹"

- **采购部没有统一知识平台**（没有 Glean / 飞书 / 钉钉 / Confluence）
- **政策查找靠人**——这正是 V0 `R_SPIKE_REVIEW` 想解决的痛点

## 3. C9-C10 判断标准（C 组）

### C9. PR 合规判断标准

> 原话: "有简单的说明，但常常执行随意，**基本靠采购部门人工裁定**"

- **政策成文 + 执行随意**——这是 ECE 切入的最佳状态（与 `customer-profile.procurement.md` §1 "采购政策成熟度"列完全匹配）

### C10. 审计史

> 原话: "每年都有 2-3 起，不合规和比价不足都存在，后者很严重，导致采购成本过高，审计严格时成本会降低，**忽高忽低**"

**关键信号**：
- **每年 2-3 起不合规**（频次足够触发付费动力）
- **"审计严格时成本会降低"** = **审计压力 → 采购成本下降**——这反向证明"严格合规 = 真实价值"，是 **ECE 价值主张的金句**
- "忽高忽低"= 没有持续合规机制 → **ECE 价值主张：让合规常态化，不是审计前的临时收紧**

## 4. D11-D13 AI 接受度与价值（D 组）

### D11. 价值评估

> 原话: "非常大，不仅效率高，而且成本可控，但**会受到很多人的抵制（消极，不配合）**"

**关键信号**：
- **价值强 + 组织阻力强**——这两件事要分开处理：
  - 价值侧：够强（D11 信号 +1）
  - 组织阻力侧：**V0 完全没考虑**——这是新维度，需要在 `customer-profile.procurement.md` §2 Persona 加 **P6 "被影响部门代表"**（避免他们变成变革阻力）

### D12. AI 真正执行的场景

> 原话: "生成草稿合同、自动归档，历史采购记录分析与比对，外部寻源，实时行情更新"

**与 PRD §9 对照**：
- ✅ 生成草稿合同（**生成类**，LLM 友好）
- ✅ 自动归档（**执行类**，V0 关闭 actions/execute，POC 后建议开启）
- ✅ 历史采购记录分析（**检索+分析类**，V0 demo 已具备）
- ✅ 外部寻源（**新需求**，V0 不覆盖）
- ✅ 实时行情更新（**新需求**，V0 不覆盖，依赖外部数据）

### D13. 必须人工审批

> 原话: "供应商选择、价格比对、付款方式、合同审核"

**关键观察**：
- **"供应商选择 / 价格比对"** 与 A5 "哪步最需专业判断" 完全一致
- **"付款方式 / 合同审核"** 是新场景——V0 没覆盖
- **AI 不能动的边界很清楚**：所有"判断 + 金额责任"环节

## 5. E14-E15 商业路径（E 组）

### E14. 决策人 + 预算

> 原话: "一般采购部门时需求者，有预算申请权，但系统选型、实施、验收、付款由 IT 主导采购协助"

**关键信号**：
- **采购部是需求方 + 有预算申请权**，**IT 是选型/实施/付款主导**——这与 GRC 方向（E14 写"安全/合规/内审"预算）**完全不同**
- **P2 候选不是 CFO**，而是 **P2 = IT 负责人**（新 Persona）

### E15. 付费条件

> 原话: "PR 量"

- **按 PR 量付费**——明确
- 与 `validation-metrics.procurement.md` §2 公式"Pilot意愿 + Pay信号"权重对应

## 6. C3 顺带探询（§2）

### C3-1. 评标对比方式

> 原话: "公开应答，现场集中抽签、述标、答疑、评标"

- **评标流程**：抽签 → 述标 → 答疑 → 评标（**线下集中**，不是异步）
- V0 demo 不涉及评标场景——这是 C3 候选方向的真实痛点

### C3-2. AI 对照矩阵有用性

> 原话: "非常有用，但不足够"

- **有用但不足够**——可能是因为应答文本是非结构化的，AI 自动生成对照矩阵**不能替代专家判断**
- **C3 方向需要更深的 Domain Reasoning**，V0 spike 不够
