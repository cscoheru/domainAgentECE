# Customer Validation Metrics（验证指标与 POC 触发）

> Phase: Gate 5
> 用途：5 场访谈后统一评估，决定 POC / Pivot / 继续验证

## 1. 逐场记录指标（11 项，PRD #27）

| 指标 | 记录方式 | 判读 |
|---|---|---|
| Problem Severity | 1–5（受访者自评+我们评估） | ≥4 为强信号 |
| Frequency | 次数/年（续证+内审+客户问卷） | ≥2/年 |
| Current Cost | 人×周×时薪估算 | ≥3 人周/年 |
| Current Workaround | 现有工具与土办法 | 越土越好 |
| Data Availability | 证据所在系统清单+权限状况 | 可导出/可接 API 为佳 |
| AI Acceptance | D12/D13 答案 | 有明确"可执行边界"为佳 |
| Security Concern | B7 提到的顾虑 | 记录但不视为否决 |
| Willingness to Pilot | 三档：仅聊 / 脱敏数据 POC / 真数据 POC | 后两档为正信号 |
| Willingness to Pay | 三档：无 / 有条件 / 主动询价 | 主动询价为强信号 |
| Decision Maker | 是否受访者本人 | 否则要引荐 |
| Next Step | 是否落地为日历邀约 | 无 Next Step = 无效场 |

## 2. 需求优先级模型（访谈后评分）

```text
Score = 0.3×Severity + 0.2×Pilot意愿 + 0.2×Data可得 + 0.15×Cost + 0.15×Pay信号
≥ 3.5 → POC 推进
2.5–3.5 → 补访谈（累计 ≥8 场）再判
< 2.5 → 回到 product-ranking.md 启动 C3/C4
```

## 3. POC 触发条件（PRD #28，全部满足）

- [ ] 至少 2 家客户确认相同痛点（Severity≥4 且痛点描述同源）
- [ ] 至少 1 家愿意提供脱敏真实数据（快照导出亦可）
- [ ] 该客户愿意安排技术+业务人员各 1 名对接
- [ ] 双方共同定义成功指标（建议：单控制项证据归集 ≤10 分钟人工介入；缺口识别召回 ≥80%）

## 4. 假设校准点（第 3 场后检查）

| 原假设 | 校准问题 | 若被推翻 |
|---|---|---|
| "人工证据类控制是痛点" | 受访者是否主要痛在云配置测试？ | 转向与 Vanta 生态互补/集成定位 |
| "3–4 周准备周期" | 实际人周数 | 修正 Business Outcome 模型 |
| "内审是第二场景" | P2 受访者反馈 | 提升/降低 C3 权重 |
| "愿意给脱敏数据" | 实际数据政策 | POC 改为客户环境内部署（Glean 在客户侧） |

## 5. 停止/转向条件（诚实执行）

- 连续 3 场 Severity<3 → 该方向降级
- 5 场中 0 家愿 POC → 回到候选表，启动 C3（采购评标）验证
- 发现更强相邻痛点（如客户安全问卷 C9）→ 记录并评估并入 C1 路线图，**不擅自扩 MVP 范围**
