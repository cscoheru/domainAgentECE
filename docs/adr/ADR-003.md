# ADR-003: Permission Engine 自建,Permission Before Intelligence 铁律

- Status: Accepted
- Date: 2026-09-13
- Deciders: 产品负责人(创始人)+ AI 架构师(Phase 3/4)
- Phase: 4 — Build/Buy/Integrate/Partner

## Context

1. Capability Matrix v2 Row 5 + Phase 3 §4.1:Permission Engine = **Build + Integrate(语义)**。
2. Glean 已实现并对外暴露完整权限机制: [C06] 源系统 ACL 继承 + [C07] 实时权限同步 + [C16] Verification API + [C19] MCP tenant 级隔离 + [C36] Agent Identity scoped credentials。Glean 实现经过 7 年企业信任积累(RED_TEAM v3 §0.2)。
3. 我方无可达市场的 Glean 客户(v3 Red Team §0.6 U-G1),且 v0 部署形态 = 私有化(ADR-009 缓交横向基础设施)。
4. Permission Before Intelligence 是 ECE 产品 P2 原则;E2 套件(Unauthorized Context Exposure = 0)是 CI 一票否决门槛(EVALUATION.md §1)。

## Decision

1. **Permission Engine 自建**:实现 ACL 模型(subject: user/role/department × object: entity/document × effect: allow/deny),存 `acl_entries` 表(DATA_MODEL §3)。
2. **判定顺序**:deny > user > role > department > classification 默认 > 默认 deny。文档另受 classification 矩阵(public/department/management/finance/procurement/confidential)。
3. **执行位置**:所有 Store 读方法以 `PermissionScope` 为必传参数;**SQL 子查询过滤**(非取回后丢弃,更非 prompt 约束)。
4. **Actions 写回 v0 强制关闭**([C08] 借,但路由级 403 + env kill-switch 双保险)。
5. **Glean 语义借用**:Agent Identity([C36] beta)的"scoped credentials + audit attribution"概念可作为 Phase 5+ 借鉴,但 v0 不实现(ECE v0 actingUser 写死)。

## Consequences

- ✅ Permission Before Intelligence 铁律可验证、可审计(E2 套件 CI 阻断)
- ✅ 间接泄露面收敛为 Agent 输出层(EVALUATION §3 专项覆盖)
- ✅ 与 Glean 同模式([C06][C07]),我方工程能力可达成
- ⚠️ 每条查询都携带 PermissionScope 子查询,复杂度 + 少量性能成本 — 用索引与 PermissionScope 预编译对冲
- ⚠️ Agent Identity 等 v2 Glean 特性([C36] beta)我方 v0 不实现;Phase 5+ 视 Robin 会谈决定是否吸收

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 取回后过滤(post-filter) | 泄露面扩大到日志/缓存/中间结构,否决 |
| LLM prompt 约束("请不要泄露") | 不可验证、可被注入绕过,明确禁止(PRD §13) |
| 全部借用 Glean | 可达市场无 Glean 客户(U-G1),无法集成 |
| 仅借语义不实现 | E2 = 0 无可验证基础,铁律失效 |
