# ADR-010: Domain Reasoning 自建(规则优先 + LLM 轻量,极高 IP)

- Status: Accepted
- Date: 2026-09-13
- Deciders: 产品负责人(创始人)+ AI 架构师(Phase 3/4)
- Phase: 4 — Build/Buy/Integrate/Partner

## Context

1. Capability Matrix v2 Row 16 + Phase 3 §4.1:Domain Reasoning = **Build**(极高 IP)。
2. [C23] (STRONGLY_INFERRED): Glean 未提供领域推理能力。
3. ECE ARCHITECTURE §8 已固化 Procurement Agent 组成:Role/Goal + **领域规则(比价阈值、审批链完整性、价格偏离带)** + LLM + 结构化输出。
4. v3 Red Team §0.8: **"规则优先架构意外命中中国约束"** — 确定性推理(充分性/新鲜度/覆盖度)不依赖前沿模型;LLM 只做文档理解与解释 — 恰好是国产开源模型友好的负载分布。LLM Provider Independence(ADR-006 — ECE 内部编号)+ 私有化部署 + 国产开源模型 = v3 主路径 D 的关键技术支柱。
5. PRD #36 H4: "Context Engine 可以脱离具体 LLM" — 双模型对照(E6)证明。

## Decision

1. **ECE 自建领域规则引擎**:`src/domain_packs/procurement/agent/` + `src/ece/reasoning/`,纯 Python 函数实现确定性推理(比价触发 / 审批链完整性 / 价格偏离带 vs 历史价 vs 市场参考价)。
2. **LLM 职责限定**:仅做文档理解(控制项-证据映射抽取)+ 综合表述(把规则 findings 翻译成自然语言解释);**不参与确定性判断**(违反 LLM 不可知铁律)。
3. **结构化输出**:conclusion / reasoning_summary / risks[] / recommendation / evidence[] / confidence(EVALUATION §3 / ARCHITECTURE §8);每条 evidence 必须引用 package 内 source_id。
4. **双模型对照**(EVALUATION §5 H4):同一 E6 问题集,模型分别接 DeepSeek / Qwen / GLM(vLLM 或 Ollama 本地)与一个前沿闭源模型,验证"规则优先 + 开源模型"组合在国产约束下的可行性。
5. **Procurement Agent v0 范围**(TASKS Sprint 5):评估采购申请 / 供应商分析 / 报价合理性 / 政策匹配 / 历史比较 / 风险提示 / 证据引用。

## Consequences

- ✅ 极高 IP 价值:Domain Reasoning 是 Glean 未覆盖的纵深
- ✅ 规则优先 + LLM 轻量 = 国产开源模型友好(v3 主路径 D 关键技术支柱)
- ✅ 可验证、可回归(EVALUATION §3)
- ✅ LLM Provider Independence(OpenAI 兼容,支持 vLLM/Ollama/Qwen/DeepSeek/GLM)
- ⚠️ 规则库需领域专家维护;v0 假设创始人能持续提供
- ⚠️ 复杂推理(非确定性的)仍需 LLM 协助,质量取决于模型

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 让 LLM 全权推理 | 不可验证;开源模型弱;违反 Permission Before Intelligence 精神 |
| 借 Glean Agent Builder workflow 推理 | [C11] workflow 细节 UNKNOWN;Glean 不卖领域推理能力 |
| 仅做规则不做 LLM | 文档理解与表述仍需 LLM(纯规则不友好) |
