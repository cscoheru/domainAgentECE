# ADR-004: MCP Tool Layer 自建 + Integrate (事实标准)

- Status: Accepted
- Date: 2026-09-13
- Deciders: 产品负责人(创始人)+ AI 架构师(Phase 3/4)
- Phase: 4 — Build/Buy/Integrate/Partner

## Context

1. Capability Matrix v2 Row 9 + Phase 3 §4.1:MCP Tool Layer = **Build + Integrate**。
2. [C19] Glean Remote MCP Server 是 Glean 平台的核心集成通道(tenant 级、权限感知、OAuth DCR、可 MDM 部署)。
3. [C37] Fall'25 矩阵明确 **remote MCP servers 状态为 beta**。
4. [C39] Glean 官方运营 developers.glean.com MCP server,支持 Claude Code / Cursor / Codex / Gemini CLI 一键集成;原文: `claude mcp add glean-developer-docs https://developers.glean.com/mcp --transport http --scope user`。
5. MCP 已是 Agent 工具层事实标准(Claude Code / Cursor / Codex / Gemini CLI / OpenAI Agents SDK 等均原生支持,PRD §6 M06 明确)。

## Decision

1. **ECE Tool 层原生 MCP 化**:自建 MCP server 实现 + 自建 MCP client 集成 Glean。
2. **内置最小工具集**(ARCHITECTURE §8):search / get_record / create_task / send_message + 后续扩展。
3. **与 Glean MCP 互操作**:ECE 既作为 Glean 的 MCP client(借 Glean search/get_record),也作为 MCP server 暴露给 Claude Code / Cursor 等开发工具。
4. **不实现 Glean Agent Toolkit 完整表面**:只暴露 ECE v0 需要的最小集,Phase 4+ 按需扩展。
5. **Phase 5+ 考虑**:Partner built Tools 暴露(Robin Q5 必问)。

## Consequences

- ✅ 与 Glean、Claude Code、Cursor、Codex、Gemini CLI 等 MCP-compatible runtime 互操作
- ✅ 我方自建 get_record/create_task 可被外部 runtime 直接调用,降低集成成本
- ✅ MCP 事实标准保护了未来 vendor lock-in 风险
- ⚠️ MCP spec 仍在演进(2025-2026 标准化中),需关注 breaking change
- ⚠️ v0 工具集最小,Phase 4+ 按 PRD §6 M06 评估是否扩展到 OpenAPI 自定义 Action

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 只做 OpenAPI 自定义 Action | 非事实标准;不与 Claude Code 等互操作 |
| 只借 Glean Agent Toolkit | 锁定 Glean;Phase 4+ 不灵活 |
| 不实现 MCP,只走 REST | 与 2026 工具层标准化方向背离 |
