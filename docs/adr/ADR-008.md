# ADR-008: Domain Evaluation 自建(业务正确性评估,极高 IP)

- Status: Accepted
- Date: 2026-09-13
- Deciders: 产品负责人(创始人)+ AI 架构师(Phase 3/4)
- Phase: 4 — Build/Buy/Integrate/Partner

## Context

1. Capability Matrix v2 Row 14 + Phase 3 §4.1:Domain Evaluation = **Build**(极高 IP)。
2. [C14] Glean Agent Observability 包含 adoption / error rates / up/down votes / ROI(**平台级**指标,CONFIRMED)。
3. [C22] (STRONGLY_INFERRED) + **[C38 收紧]**: Glean 官方未公开提供**领域正确性/业务推理质量**评估;官方 Agent 治理文案出现 "evaluations" 一词,但语义指向 execution-path 与 performance,**不等于 domain correctness**。
4. v3 Red Team §0.8 明确: "若 Glean 观测仍停留在平台级指标,则 Domain Evaluation 是我们最高 IP 价值的空白层"。
5. ECE EVALUATION.md §1 E1-E6 已设计 6 套评测套件;EVALUATION §5 H3 要求与"纯向量 RAG 基线"对照证明 ECE 优势。

## Decision

1. **ECE 自建 Domain Evaluation 套件**(E1 Entity Resolution / E3 Context Completeness / E4 Relationship / E5 Temporal / E6 Agent 端到端;E2 Permission 是 CI 一票否决门槛)。
2. **ECE v0 自建"业务正确性"评测维度**:不仅看 LLM 输出格式对错,看业务规则是否被正确应用(如:四类推理是否触发 / 缺口是否被识别 / 证据是否充足)。
3. **基线对照**:同一 E6 问题集跑"纯向量 RAG 基线"(`tests/evaluation/baseline_rag.py`),报告并排对比 — 这是 PRD §36 H3 的实证。
4. **双模型对照**(国产开源 + 前沿闭源)证明"规则优先 + 开源模型"组合成立(ADR-006 + v3 §0.7 中国约束)。
5. **永不模仿 Glean 同款 execution-path 评估** — [C22] 推断为我方 IP,主动放弃模仿。

## Consequences

- ✅ 最高 IP 价值:Domain Evaluation 是 Glean 未覆盖的纵深
- ✅ 可验证、可对比(纯 RAG 基线 + 双模型)
- ✅ 业务正确性评估是客户付费决策的核心证据
- ⚠️ v0 评测集规模有限(E1 ≥50 / E3 ≥100 / E4 ≥30 / E5 ≥30 / E6 ≥50),Phase 5+ 扩规模
- ⚠️ "业务正确性"定义需与客户行业专家对齐,Phase 5+ 行业化

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 仅采 Glean 平台级指标 | [C22] 不覆盖业务正确性,放弃我方最高 IP |
| 模仿 Glean execution-path evaluations | [C38] 语义不同,模仿即失去差异化 |
| 不评测 | PRD §13 明确"没有测试的功能不算完成",EVALUATION 是核心模块 |
