# ADR-005: Enterprise Graph 自建(简化版)+ 借 Glean API(扩展)

- Status: Accepted
- Date: 2026-09-13
- Deciders: 产品负责人(创始人)+ AI 架构师(Phase 3/4)
- Phase: 4 — Build/Buy/Integrate/Partner

## Context

1. Capability Matrix v2 Row 3 + Phase 3 §4.1:Enterprise Graph = **Build + Integrate**。
2. [C02] Glean 官方明确 Enterprise Context = Search Index + Entity System + Permission + Context Assembly 之综合([C18] reason over KG 佐证)。
3. [C03] Enterprise Graph 内部 schema 可否自定义/API 读写 **UNKNOWN** — Robin 会谈必问 Q9。
4. Phase 5 Platform Kernel Definition 时需决定:若 Glean 允许 schema 自定义,采用 Glean Adapter 模式;否则 ECE 自建简化版图谱独立运行。
5. ECE v0 走"Postgres 一库承担"路线(ADR-009 缓交横向基础设施),`entities + relationships + entity_revisions` 三表即可表达 graph 核心。

## Decision

1. **ECE v0 自建简化版图谱**:Postgres `entities` + `relationships` 表(DATA_MODEL §1-2);temporal 谓词 current/as_of/between 通过 SQL 子查询实现(ARCHITECTURE §7)。
2. **Phase 5+ 视 Robin 会谈决定 Glean 集成路径**:
   - 若 [C03] CONFIRMED schema 自定义 → 写 GleanAdapter,通过 Indexing API 推送自定义数据源
   - 若 [C03] 仍 UNKNOWN → 推迟 Glean 集成,ECE 自建路径独立运行
3. **不重建 Glean Enterprise Graph 全部能力**(Search/Graph/Permission 复杂度极高),只承担 ECE 域内必需子集。
4. **Entity Resolution 是本决策的伴随产物**(见 ADR-007):跨系统归一由 ECE 自建。

## Consequences

- ✅ v0 不被 Glean Enterprise Graph 复杂度阻塞
- ✅ 简化版图谱(3 张 Postgres 表)满足 ECE v0 全部需求
- ✅ Phase 5+ 路径灵活:可借 Glean Adapter,也可继续自建
- ⚠️ 若 [C03] 之后显示 Glean 不支持 schema 自定义,我们的 graph 与 Glean 完全独立,需要客户环境二选一
- ⚠️ 跨系统 Entity Resolution 必须自建(高 IP 但也高投入)

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 完整重建 Glean Enterprise Graph | 7 年护城河,违规铁律(v3 Red Team §0.7) |
| 完全不建图,只用文档 + 向量 | 无法表达关系与时间(temporal) |
| 只借 Glean Indexing API,无本地 schema | 离线运行失败,违反私有化(ADR-009) |
