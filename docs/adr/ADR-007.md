# ADR-007: Entity Resolution 自建(跨系统实体归一)

- Status: Accepted
- Date: 2026-09-13
- Deciders: 产品负责人(创始人)+ AI 架构师(Phase 3/4)
- Phase: 4 — Build/Buy/Integrate/Partner

## Context

1. Capability Matrix v2 Row 4 + Phase 3 §4.1:Entity Resolution = **Build**(高 IP)。
2. [C18] Glean Agents "reason over the knowledge graph" — 隐含 Glean 内部有 Entity Resolution 机制,但**具体算法 / 跨系统归一细节 UNKNOWN**。
3. [C23] 推断 Domain 层(含 Entity Resolution 跨系统变体)是 Glean 未覆盖的纵深。
4. 企业核心痛点:同一供应商在 ERP / OA / 合同系统 / 财务系统 名字不同(XX科技 / XX科技有限公司 / XX科技(广州)有限公司);若不归一,Context Assembly 第 4 步会重复 / 漏召回。
5. ECE v0 范围(Procurement 领域):供应商归一 + 人员别名 + 历史组织变更;**LLM 不得直接成为企业事实**(ARCHITECTURE §6)。

## Decision

1. **ECE 自建渐进流水线**(ARCHITECTURE §6):exact(source_id) → normalized_name → alias 表 → 规则(剥离"有限公司/华南"等后缀)→ embedding 相似度(τ=0.92,以下进人工复核队列)→ LLM 辅助(只产 candidate)。
2. **结果落 `entity_aliases` 表**(canonical_id, source_system, source_ref, method, confidence;DATA_MODEL §1)。
3. **`method='llm'` 一律 `status='pending'`**,只有 `confirmed` 参与 Assembly(铁律:LLM 猜测不得直接成为企业事实)。
4. **评审集 E1** ≥95% 准确率,**歧义例必须 `resolved:false` 而非猜错**(EVALUATION §1)。
5. **confidence < 0.9 一律进人工队列**,人工通道确认后才升级到 `confirmed`。

## Consequences

- ✅ 可验证、可审计(E1 套件 + 人工通道)
- ✅ LLM 不得绕过归一过程直接写企业事实
- ✅ 跨系统归一是 Glean 未充分覆盖的纵深([C23] 推断)
- ⚠️ v0 评审集仅 ≥50 例,Phase 5+ 扩到 ≥500 例覆盖更多边界
- ⚠️ embedding 相似度阈值 (τ=0.92) 需实际数据校准

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 完全靠 LLM 归一 | LLM 猜测不得成为企业事实(PRD 禁止) |
| 仅做 exact match + normalized_name | 不处理同供应商多名称(企业核心痛点) |
| 借 Glean Entity Resolution | [C18] 暗示 Glean 有但细节 UNKNOWN;且 v3 U-G1 可达市场无 Glean |
