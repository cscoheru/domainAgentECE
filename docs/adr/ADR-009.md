# ADR-009: Domain Ontology 自建(控制-证据映射,极高 IP)

- Status: Accepted
- Date: 2026-09-13
- Deciders: 产品负责人(创始人)+ AI 架构师(Phase 3/4)
- Phase: 4 — Build/Buy/Integrate/Partner

## Context

1. Capability Matrix v2 Row 15 + Phase 3 §4.1:Domain Ontology = **Build**(极高 IP)。
2. [C23] (STRONGLY_INFERRED): Domain 层(领域本体/推理/评估)是 Glean 未覆盖的空白。
3. v3 Red Team §0.7 "工作流优先、上下文随行":**领域上下文 = 领域工作流的副产物**,随使用被持续维护加深,沉淀为垂直领域资产。这是 v0.1 之后最深的 IP 复利来源。
4. ECE v0 (Procurement 领域) 必须从 SOC2 → ISO27001 → 等保 → 内控 等框架**框架无关性**出发;换框架 = 内容工作,不是架构工作(ADR-010 领域包隔离铁律)。
5. PRD #40 明确 "Task → Context Specification" 是核心抽象;YAML 形式的 spec 是领域本体落点。

## Decision

1. **ECE 自建 Domain Ontology**:YAML 形式 Context Specification(spec / version / root_entity / requires.entities / requires.relationships / requires.documents / requires.structured_data / temporal / limits)(ARCHITECTURE §2.1 + ece/docs/ADR-010)。
2. **ECE v0 落点**:`src/domain_packs/procurement/context_specs/evaluate_purchase_request.yaml` — 12 个 SOC2 CC 控制项(red team v3 已要求中国化,Phase 5+ 换框架)。
3. **Ontology 入库校验**:允许的关系三元组由 `src/domain_packs/<domain>/ontology.yaml` 声明,入库时校验,未声明组合 → 拒绝(DATA_MODEL §2 末段)。
4. **跨框架扩展**:Phase 5+ 添加 ISO27001 / 等保 / 内控的 ontology 时,**新包 1-2 周,不动引擎**(Sprint 6 选做 audit 演练)。
5. **评估集与 spec 版本绑定**:评测集(E1-E6)随 spec_version 走 git 评审,变更可回归(EVALUATION §3)。

## Consequences

- ✅ 最高 IP 价值:Domain Ontology 是 Glean 完全未覆盖的纵深([C23])
- ✅ 框架无关性:换 SOC2 → ISO27001 = 内容工作,不是架构工作
- ✅ 复利资产:随客户使用,本体 + 评估集持续加深(竞品抄不走)
- ⚠️ v0 仅覆盖 SOC2 12 CC 控制项(red team v3 标记需中国化)
- ⚠️ Ontology 入库校验是手动维护,Phase 5+ 考虑自动 lint

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 借 Glean Enterprise Graph schema(若 [C03] CONFIRMED) | Glean 仍不支持**领域本体**(仅通用 KG schema),核心 IP 仍需自建 |
| 用通用 LLM 抽取本体 | 不可验证、版本漂移,违反 ontology 必须可追溯原则 |
| 借用 SOC2 公开 TSC | TSC 是公开框架,任何审计师可复刻(red team §三 IP 薄);需叠加**评估集 + 跨框架映射 + 持续维护**才形成护城河 |
