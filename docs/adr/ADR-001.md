# ADR-001: Context Adapter 抽象 + Mock-first 实现策略

- Status: Accepted
- Date: 2026-09-03
- Deciders: 产品负责人（创始人）+ AI 架构师（Cline）

## Context

1. Glean Platform API 处于 experimental preview（证据 C15），且 Glean 走企业销售流程——MVP 阶段（2–4 周）几乎不可能获得真实 Glean 租户。
2. Glean Agent Builder workflow 能力细节 UNKNOWN（C11），不能作为 MVP 架构前提。
3. 项目最高目标是**尽快拿到客户反馈**，不是平台完整性。

## Decision

1. 定义 `ContextAdapter` 统一接口（search / get_entity / get_person / get_organization / get_customer / get_project / get_metric / get_record / create_task / send_message / update_record），Domain 层**只依赖此接口**。
2. MVP 用 `MockAdapter` 实现全部接口语义（含角色门控与溯源字段），配 Mock Enterprise 数据集。
3. `GleanAdapter` 只写骨架：每个方法留 TODO 并标注证据编号（C04/C08/C16 等），禁止臆造接口细节。
4. CI 强制：`src/domain/**` 不得出现 glean/mcp 关键字。

## Consequences

- ✅ MVP 不被 Glean 接入阻塞，2–4 周可见客户
- ✅ Mock 与未来 Glean 实现接口一致 → 切换成本=一个工厂函数
- ✅ 客户没有 Glean 时，REST 直连路径仍可用（portability.md）
- ⚠️ Mock 检索是内存过滤，不模拟真实相关性排序——Demo 中以"权限感知+类型过滤"为演示重点，不吹嘘检索质量
- ⚠️ 若 Glean 真实接口与假设差异大，POC 阶段需要一次适配层修订（已预留 C 编号 TODO 定位）

## Alternatives Considered

| 方案 | 否决理由 |
|---|---|
| 直接申请 Glean 试用并实接 | 周期不可控，阻塞客户验证（违反最高目标） |
| 不做抽象、直接调 Glean SDK | 违反 CLAUDE.md 第 8/13 节；锁定且无法给无 Glean 客户演示 |
| 只做抽象不写 Glean 骨架 | POC 时无评估基础；骨架+TODO 是廉价的未来路径图 |
