# 咨询知识库演示脚本（10–15 分钟）

> 面向：潜在客户（咨询合伙人 / 知识管理负责人 / 交付负责人）
> 语言：业务语言，不出现内部字段名、不提模型名、不讲架构分层
> 现场：浏览器打开演示起点即可，**不需要任何截图**
> 版本：OEI-013 / 2026-09-26

---

## 0. 开场（1 分钟）

打开浏览器，进 **视图 D · 咨询知识库（客户演示）**。

> 「这是一个给咨询团队的**知识工作台**。今天不演示功能清单，就演一条完整的路径：
> **客户问一个问题 → 知识库怎么答 → 再把你自己的一份案例放进去看它怎么被找回来。**
> 全程 10 分钟，三步都是现场跑的。」

**三条要说在前面的话（也是这个演示的诚实底色）：**

1. 下面看到的**每一条命中都带出处**，可以点开看依据。
2. 知识库是**关键词检索**，不是「会聊天的搜索」。这一点待会儿会具体演给你看。
3. 引擎召回这一层**现在还不够好**，我们待会儿会把它现在真实的样子给你看，包括它现在做不到什么。

---

## 第一幕 · 一个问题（2 分钟）

**做什么**

1. 指着输入框：里面已经预填好一句**客户会真的问出口的话**：

   > 客户想做一次采购成本诊断, 该从哪下手

2. 强调：这不是关键词，是**一句人话**。

**要讲的点**

- 咨询顾问每天收到的就是这种句子。所以第一件事是：**知识库得先听懂人话。**

**（可选）** 点一下旁边的示范问题芯片，换一句：

| 芯片 | 会输入的问句 |
|---|---|
| 项目风险披露 | 我们的项目风险该怎么向客户披露 |
| 供应链韧性 | 给制造业客户评估供应链韧性 |
| 渠道库存 | 帮零售客户看渠道库存周转 |

---

## 第二幕 · 知识库怎么答（4 分钟）

### 2.1 先看「它听懂了什么」（30 秒）

输入框下面会出现一行蓝色说明，写着系统**实际拿去检索的词**，例如：

> 这句话不是一个关键词, 知识库没直接命中. 已按其中的业务词检索: 采购成本 / 诊断 — 合并去重后 11 条.

**要讲的点（这是全场最诚实的一段，别跳过）：**

- 「知识库现在做的是**关键词匹配**。一句完整的话它匹配不到 —— 这是我们**当着你的面**承认的缺口。」
- 「所以我们加了一层**固定规则的改写**：把人话里出现的业务词挑出来，**并且把挑出来的词显示给你看**。」
- 「注意：这一层**没有用任何大模型**。同一句话，跑一百次，挑出来的词完全一样 —— 演示不会因为运气好坏而变样。」
- 数字：**原样投喂 → 0 条；改写后 → 11 条。**

### 2.2 目录：65 条、11 个行业轴（1 分钟）

- 静态目录 **65 条**：案例 / 方法论 / 提案打法 / 交付模板 / 风险检查 / 行业观察。
- 行业轴覆盖：零售、银行、制造业、快消、能源、医疗、物流、保险、公共部门、科技 + 跨行业。
- 强调：**这部分不依赖任何模型**，是确定性的、离线可算的 —— 演示时不会因为网络或模型抽风而变。

### 2.3 收窄：六个筛选器（1 分钟）

演示「先给候选、再收窄」：

1. 选**行业**（如 零售）→ 结果立刻收敛。
2. 再加**类型**（如 案例）→ 进一步收敛。
3. 按「重置筛选」→ 回到全量 65 条。

**要讲的点**：客户不是要"更多结果"，是要**更快排除不相关的**。

### 2.4 点开一条看依据（1 分钟）

点任意一张卡片 → 右侧抽屉打开，显示：

- **类型 / 来源 / 置信度 / 状态**
- **实践 / 阶段 / 行业 / 问题类型**
- **方法 / 交付物 / 产出**

**要讲的点**：

> 「客户真正会追问的不是"你有哪些案例"，而是"**你凭什么这么说**」。
> 这一页的每一项都能点开源头 —— 这是我们可以给客户看的东西，不是我们内部的工装。」

---

## 第三幕 · 你的文件（4 分钟）

**这一步是全场的高潮：客户自己的文件，当场进库、当场被找回。**

### 3.1 上传（1.5 分钟）

1. 滚到「③ 你的文件」→「上传一份案例」。
2. 选一份准备好的 `.md` 案例（现场建议用一份**真的**脱敏案例）。
3. 点「上传并索引」→ 状态从 `PROCESSING` 走到 **`COMPLETED`**，并显示切了多少块。

### 3.2 找回来（2 分钟）

1. 回到输入框，输入这份案例的关键词。
2. 「来自已索引文件」分组里出现**你刚上传的那份**，带**来源类型 + 更新时间 + 片段**。
3. 点开它，抽屉里显示同样的依据面板。

**要讲的点**：

> 「注意这一条不是目录里的静态素材，是**你三十秒前放进来的文件**。
> 也就是说：客户自己的方法论、自己的案例库，可以长在同一个地方。」

### 3.3 诚实交代引擎召回现状（30 秒）—— **不要跳过**

- 我们实测过：引擎在这一小撮语料上的**原始召回命中率是 0%**（同一批查询跑 3 次 × 两种模式）。
- 原因是**排序**，不是索引 —— 文档在库里、能被召回，只是排不上来。
- 产品可见层（过了权限过滤之后）**比原始层好**：过滤会把一份无关的对照文档挡掉，真文档因此有机会露出来。
- **我们没有把这一层包装成"已经修好了"**。它现在的样子就是这样，我们把它量出来了，写进了报告。

## 收尾 · 我们做了什么 / 边界 / 下一步（2 分钟）

### 我们做了什么

| 做了什么 | 可验证的说法 |
|---|---|
| 咨询知识库 65 条、11 个行业轴、6 个筛选维度 | 确定性、离线可算，演示不依赖模型 |
| 每条都带依据（方法 / 交付物 / 产出 / 来源 / 置信度） | 点开即见 |
| 现场上传 → 索引 → 当场被找回 | 单页闭环，不是录屏 |
| 人话 → 关键词：固定规则改写，**并显示改写了什么** | 同一句话跑 100 次结果一致 |
| 检索质量**实测**（不是主观感受） | 3 次 × 2 档 × 12 条查询，数字写进报告 |

### 边界（必须主动说，不等客户问）

1. **知识库检索是关键词匹配**，不是语义检索 —— 一句完整的话它匹配不到，靠我们那层规则改写兜住。
2. **引擎召回目前不达标**：原始层 hit@1 = hit@3 = **0%**；产品层被权限过滤拉回一部分，但仍不稳定。
   > **⚠️ 演示者必读 ——「来自已索引文件」那一组的条数会在重跑之间变。** 实测过：
   > 同一个 `诊断`，有一次返回 1 条，另一次返回 3 条。原因就是我们刚量到的
   > 「三次重跑只有 91.7% 完全一致」（deterministic 档是 100%，但那档召回更差）。
   > **不要预告条数**，别说「这里会出现三条」。现场就说：
   > 「这一组是引擎自己找回来的；我们这个引擎目前的稳定性恰恰是我们下一步要修的东西。」
   > 如果那一组是空的，那也**不是演示失败** —— 那正是本页想让你看到的问题，照实说。
3. **语料里还留着一份与咨询无关的对照文档**（当年做权限演示用的）。我们**已经把它从演示里挡掉**（权限过滤，fail-closed），但**它还在语料库里** —— 因为删它是不可逆操作，我们**等你看过重测数字再决定**。
4. **演示是单域（咨询）**。采购 / 知识管理 / 企业合规三个域共享同一底座，但这个演示只讲咨询域。
5. **权限演示还不是真认证**：现在能演「同意份查询、两种身份、不同召回」，但讲**权限分层**之前必须先做真认证。

### 下一步（按优先级）

1. **移除 / 归档那份对照文档**（等你点头）—— 之后引擎召回才有干净的基线。
2. **检索排序**：已经确认是排序问题；修完用同一套评测集复测。
3. **目录检索语义化**：让人话直接命中，不再依赖那层规则改写。
4. **真认证**：权限分层演示的前置条件。
5. （远期）客户 POC / 私有化部署 —— 需要客户侧需求触发，不是现在能承诺的。

## 附：常见问题

| 客户问 | 怎么答 |
|---|---|
| 数据从哪来？ | 目录是脱敏的真实案例 + 方法论整理；来源标签逐条标了。 |
| 会不会瞎编？ | 目录层是确定性检索，不会编；每条都能点开看依据。 |
| 能接我们自己的库吗？ | 能 —— 第三幕演示的就是接一份自己的文件。 |
| 支持多少人/多大规模？ | 现在不做容量承诺；这是演示台，不是交付级部署。 |
| 检索怎么这么慢/这么差？ | 直说：慢和差都是真的，我们已经量出来了（见「边界」）。 |
| 为什么这一组的条数每次不一样？ | 直说：这组是引擎召回，我们现在**还做不到稳定**（实测三次重跑只有 91.7% 完全一致）。目录层那一组是确定性的，每次一样。 |
| 那份对照文档还在吗？ | 还在语料库里，但**客户看不到** —— 逐条权限过滤已经把它挡在外面了。删它是不可逆的，我们等你决定。 |
