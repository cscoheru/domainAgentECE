# 决策：为什么不做 Dify、为什么用 Onyx CE、边界怎么划

> 记录时间：2026-09-23 ｜ 决策状态：**已锁定**

---

## 1. 起点与问题

项目最初按 Track A（Glean 企业上下文底座研究）+ Track B（ECE v0 开发）双轨推进。ECE v0 的 cut-041～045 已完成并部署，但用户实际打开线上演示后的反馈是决定性的：

> "核心的多域实时演示就是一个六步闭环，看到的就是命令行的展示……正常人都不会觉得这是一个系统，更像一个网页脚本演示，用了几个业务的词汇，太单薄了。"

由此得到两条结论：

1. **演示问题不是 UI 皮肤问题，而是底座缺失**。没有真实的知识/上下文承载层，前端再包装也还是脚本。
2. **企业 Agent 的瓶颈是上下文与权限**。所以 ECE 需要一个真正的"内容与检索引擎"来承载知识，而不是继续自研分词、向量、检索这些通用能力。

## 2. 候选方案与结论

### 2.1 Dify — 不采用

对 Dify 的评估结论（工作流 + RAG + Agent + 模型管理 + 可观测性一体平台）：

- **不进 ECE 内核**：它的抽象（app/workflow/agent 编排）与 ECE 的领域对象、权限、审计模型不是一套语言，强行嵌入会让 ECE 内核被外部框架的领域模型污染。
- **不做代码切分整合**：从大仓库里切出"知识库部分"会持续背上与上游分叉的维护成本，升级即冲突。
- **也不做 black-box sidecar**：它无法被物理切块，等于必须完整部署整个 Dify，长期是运行负担与升级负担，而我们只需要其中的文件处理与检索。

**结论：放弃 Dify。**

### 2.2 Onyx CE — 采用

评估结论：

- **中后期契合度高**：定位就是企业级内容与检索引擎，接口与前端都现成，可作为"统一 API + 前端基座"快速让系统有样子。
- **CE 已覆盖本次所需**：文件知识库、索引与检索、基础 ACL、MCP、project / user files、GPU embedding。
- **CE 边界清晰（EE 才有）**：外部源权限同步、用户组、SSO/SCIM、高级审计。这条边界正好把"身份/权限/审计"留给 ECE —— **与我们要自己掌握的 IP 完全吻合，不是缺陷而是分工**。
- **资源可承受**：i9 + RTX 4070 上以标准档起步可行（实测数据见 `DEPLOYMENT-STATUS.md`）。

## 3. 锁定的架构边界

```
        ECE（自有，必须掌握）
  ┌──────────────────────────────────────┐
  │ 身份 / 权限 / 来源 / 审计 / 证据       │
  │ 领域对象 / 领域工作流 / 领域 Agent     │
  │ 面向客户的 UI 与演示场景               │
  └───────────────┬──────────────────────┘
                  │  Content Engine Port（我们自己定义的接口）
  ┌───────────────▼──────────────────────┐
  │  Onyx CE（可替换：内容与检索引擎）      │
  │  文件知识库 / 索引 / 检索 / 基础 ACL    │
  └──────────────────────────────────────┘
```

一句话：**ECE 拥有身份、权限、来源和审计；Onyx CE 只做可替换的内容与检索引擎**，包括它的 API 与前端都作为自研技术栈的一部分来使用。

## 4. 目标档位与硬件路线

- 目标客户档位：**企业档**；落地路径：**从标准档起步**再向企业档演进。
- 现有 VPS（4 核 8G）**不作为主要承载**：Onyx 标准档在该规格上不现实；公网 `corln.rana.asia` 另有 Cloudflare 526 未解决。
- 现实方案：**i9（i9-13900H / 16G / 1T SSD / RTX 4070 8G）作为开发与演示机**；未来真正上线时再申请 16G/32G VPS，或按客户要求本地部署。

## 5. 尚未决定 / 风险

| 项 | 说明 |
|---|---|
| 关系型/向量库替换 | Onyx CE 自带 Postgres + OpenSearch；长期是否换成 ECE 自有存储层未定 |
| 检索质量基线 | 尚未建立评测集（OEI-001 起开始积累主观 + 可复现的检索证据） |
| 企业档能力缺口 | 用户组/SSO/外部权限同步在 EE；若客户要求，需 ECE 侧自建或买 EE |
| 多租户 | 当前单实例；演示阶段不做多租户 |
| 资源余量 | WSL 仅 11Gi 可用内存，Onyx 栈约占 7.5Gi，剩余约 2.9Gi，跑大索引或并发演示有风险 |
